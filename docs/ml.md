# ml.md — ML/LLM-задачи и подходы

## 1) Какие задачи решает система

Минимальный набор:
- Topic classification: определить тему/категорию тикета.
- Risk classification: определить риск (safe/risky/unknown) для выбора режима обработки.
- Retrieval: найти похожие тикеты или фрагменты базы знаний (KB) для обоснования решения.
- Answer drafting (опционально, асинхронно): сформировать черновик ответа с опорой на evidence.

## 2) Почему такой стек: правила vs ML vs embeddings/RAG vs LLM

### 2.1 Что решать правилами

- Политики риска (категории, которые нельзя авто-закрывать).
- Простой PII-фильтр/маскирование (в PoC).
- Быстрый роутинг по ключевым атрибутам (канал, теги, “инцидентные” ключевые слова).

### 2.2 Где уместна классическая ML-модель

- Topic classification на исторических размеченных тикетах (например, линейная модель/градиентный бустинг/легковесная нейросеть).
- Risk classification как отдельная задача (если риск определяется не только категорией, но и контекстом).

Что даёт:
- Дешевле и стабильнее, чем LLM на hot path.
- Контролируемые метрики, быстрый инференс.

### 2.3 Где нужны embeddings/retrieval

- Поиск похожих тикетов (case-based reasoning).
- Поиск фрагментов KB для ответа и для объяснимости (какой документ использован).

### 2.4 Где нужен LLM

- Генерация черновика ответа оператору (suggest-mode).
- Суммаризация длинных переписок для оператора.

### 2.5 Где LLM использовать не стоит

- На hot path (≤500 ms) при высоком QPS и всплесках — слишком дорого/нестабильно.
- Для категорий с высоким риском (платежи/безопасность/юридическое) без человека-в-петле.
- Для данных с PII без строгой санитизации и политик.

## 3) Baseline’ы, которые разумно запустить первыми

- Baseline A (rule-based): правила/ключевые слова + пороги confidence.
- Baseline B (classic ML): TF-IDF + linear classifier для topic.
- Baseline C (embeddings): retrieval по небольшому KB/историческим тикетам.

## 5) Валидация качества и метрики

Offline (на размеченной выборке):
- Topic: macro-F1, confusion matrix по критичным классам.
- Risk: recall по risky-классам (важнее не пропустить риск), precision для снижения ложных эскалаций.
- Retrieval: recall@k, MRR@k (на “кликаемых” релевантных статьях/тикетах).

Online (в пилоте):
- Доля тикетов, корректно маршрутизированных без эскалации назад.
- Reopen rate / escalation rate.
- CSAT/SLA (как guardrails).

- Сохраняем:
  - финальные решения оператора (approve/edit)
  - причины отказов/эскалаций
  - outcome-метрики (reopen, CSAT)
- Используем:
  - для обновления правил
  - для переобучения моделей
  - для обновления KB и retrieval-индекса
